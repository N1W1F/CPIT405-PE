1Which unit is relative to the font size of the root element?

What it asks: Pick the unit whose size depends on the page's base (root) font size.
a) em
b) rem
c) vw
d) px
Show answer
b) rem. em is relative to the parent/current element.
Simple explanation
rem means root em: it is measured against the <html> font size, so it stays consistent everywhere. em is measured against the current element's (or its parent's) font size, so it compounds when elements are nested. Memory trick: rem = root.

2What color will the paragraph be?

<p id="content" class="article">Hello</p>

#content { color: blue; }
.article { color: green; }
p        { color: red; }
What it asks: Work out the final text color. When rules conflict, the browser picks the strongest one.
a) red
b) green
c) blue
d) black
Show answer
c) blue. ID beats class, class beats element.
Simple explanation
Strength order, strongest first: #id, then .class, then element name like p. Here #content wins, so the text is blue, no matter the order of the lines.

3Which selector matches only the <a> elements that are direct children of a <div>?

What it asks: Pick the symbol that selects direct children only (not everything inside the div).
a) div a
b) div > a
c) div + a
d) div ~ a
Show answer
b) div > a. div a = all descendants, div + a = next sibling, div ~ a = all following siblings.
Simple explanation
> = direct child. A space = any descendant, however deep. + = the very next sibling. ~ = all following siblings. Tip: the arrow > points from parent to child.

5What does a 5xx status code (e.g. 500, 502, 503) mean?

What it asks: What do status codes starting with 5 mean?
a) Success
b) Redirection
c) Client error
d) Server error
Show answer
d) Server error. 3xx = redirection, 4xx = client error, 2xx = success.
Simple explanation
The first digit gives the class: 2 success, 3 redirection, 4 client error (your fault), 5 server error (the server's fault). Example: 404 = page does not exist, 500 = the server crashed.

Part 2: Short Essay 4 questions

1Explain the difference between GET and POST.

What it asks: Explain how two HTTP methods differ when sending a request to the server.
Show answer
  • GET: retrieves data; parameters appear in the URL.
  • POST: creates a resource; data is sent in the request body.
  • Others: PUT full update, PATCH partial update, DELETE removes.
Simple explanation
GET asks for data, and its parameters sit in the URL (like ?q=cat), so they are visible. POST sends new data inside the request body (like a login form), so it does not show in the URL. PUT replaces fully, PATCH replaces partly, DELETE removes.

3What is the difference between JavaScript operators?

What it asks: List the kinds of JavaScript operators with examples, and contrast == with ===.
Show answer
  • Arithmetic: + - * / % **
  • Assignment: = += -= *= /= %=
  • Comparison: == != === !== < > <= >=
  • == loose (value only, converts type); === strict (value and type): 5 == "5" true, 5 === "5" false.
  • Increment/decrement: ++ --; String: + concatenates; Spread: ... unpacks arrays/objects.
Simple explanation
Group them: arithmetic (+ - *), assignment (=), comparison (== ===), increment (++). Key point: == compares the value only and converts the type, while === compares value and type. So 5 == "5" is true but 5 === "5" is false.

Possible 4th question

Internet vs Web?

What it asks: Explain how the Internet differs from the Web.
Show answer
Internet: network of networks (TCP/IP), the infrastructure. Web: information system over the Internet using HTTP.
Simple explanation
The Internet is the network itself that connects devices. The Web is the websites we open in a browser, one service that runs on the Internet, like email.

URL vs URI?

What it asks: Explain how a URL differs from a URI.
Show answer
URL locates a resource (https://google.com). URI identifies it (mailto:a@a.com). Every URL is a URI, not vice versa.
Simple explanation
A URL is an address that says where a resource is (a website link). A URI is broader: it identifies something without necessarily giving its location (like mailto:). Every URL is a URI, not the other way around.

Static vs Dynamic website?

What it asks: Explain how a static website differs from a dynamic one.
Show answer
Static: same content for all, HTML/CSS/JS, cheap. Dynamic: generated per request (PHP, Node, Python), complex.
Simple explanation
Static pages are ready-made and identical for everyone. Dynamic pages are built by the server when you ask, like a news site or your shop account.

Three tiers of web architecture?

What it asks: Name the three tiers and what each does.
Show answer
Presentation (front-end UI), Application (back-end logic), Data (database, CRUD).
Simple explanation
Think of a restaurant: the dining room you see (Presentation), the kitchen that processes the order (Application), and the storage room (Data).

Page load steps in order?

What it asks: Put the page-load steps in order.
Show answer
URL, DNS, TCP, TLS, HTTP Request, HTTP Response.
Simple explanation
Like making a phone call: type the address (URL), look up the number (DNS), dial (TCP), encrypt the line (TLS), ask for the page (Request), get the answer (Response).

HTTP basics?

What it asks: Explain the basics of HTTP.
Show answer
Stateless: each request is independent. Headers: extra info (Authorization, Content-Type, User-Agent, Cookie). Body: the data sent/received (JSON, HTML...).
Simple explanation
Stateless means the server forgets who you are after each request. Headers are extra info about the request, like the browser type. The body is the content itself, like form data.

Inline vs Block?

What it asks: Explain how inline elements differ from block elements.
Show answer
Block starts a new line, holds inline (div p ul h1 form table). Inline doesn't, can't hold block (a img span input button).
Simple explanation
Block takes a full line and starts a new one (like div). Inline only takes the space it needs inside a line (like span). A block cannot go inside an inline element.

var vs let?

What it asks: Explain how var differs from let.
Show answer
var: function-scoped, added to window. let: block-scoped, not added to window.
Simple explanation
let lives only inside the { } where you declare it. var escapes those braces and is visible outside the block, which causes bugs. Prefer let.

5JavaScript object and array

Create course with properties and a students array (two students). Add addStudent(name) that adds a new student and returns the number of students.

What it asks: Create an object with a students array and a method that adds a student and returns the count.
Show answer
let course = {
  title: "Web Applications",
  students: [{ name: "Ali" }, { name: "Ahmed" }],
  addStudent: function (name) {
    this.students.push({ name: name });
    return this.students.length;
  }
};
console.log(course.addStudent("Omar"));  // 3
console.log(course.students[1].name);    // Ahmed
If students is an array of strings, use this.students.push(name).
Simple explanation
An object uses { } with name: value pairs; an array uses [ ]. The method lives inside the object, this means the object itself, push adds to the end of the array, and length gives the count.

6What is the output? (function, array, three dots)

function sum(n, m, ...numbers) {
  let total = n + m;
  for (let i = 0; i < numbers.length; i++) {
    total += numbers[i];
  }
  return total;
}
console.log(sum(1, 2, 3, 4));
console.log(sum(1, 2));

function add(x, y, z) { return x + y + z; }
let arr = [2, 4, 6];
console.log(add(...arr));
What it asks: Write what each console.log prints.
Show answer
10   // n=1, m=2, numbers=[3,4]
3    // numbers = []
12   // spread unpacks the array
Rest ... in a function definition collects arguments into an array (must be last). Spread ... before an array unpacks it.
Simple explanation
...numbers gathers the extra values after the first two into an array. In sum(1,2,3,4): n=1, m=2, the rest is [3,4], so the total is 10. In add(...arr) the dots spread the array into three values: 2+4+6 = 12.

Quick Revision Notes

CSS

  • Specificity: inline > #id > .class :hover [attr] > element ::before. !important beats all.
  • Add CSS: external <link>, internal <style>, inline style="". Box model: content, padding, border, margin.
  • Combinators: space descendant, > child, + next sibling, ~ all siblings. : pseudo-class, :: pseudo-element.
  • Units: px cm in pt; % vw vh em rem. Float/Flexbox/Grid are optional.

HTML

  • Void (no closing tag): img br hr input meta link.
  • Input types: text, password, email, number, date, checkbox, radio, file, submit...
  • Sections: header, nav, main, article, section, aside, footer. div block, span inline.

JavaScript

  • Primitives: Number, BigInt, String, Symbol, Boolean, Null, Undefined. Object is non-primitive.
  • Functions: declaration, expression, named expression, arrow () =>, IIFE. for...of values, for...in indexes.
  • Events: inline onclick="f()" vs addEventListener("click", f); keyboard keydown/keyup.
  • DOM: getElementById, getElementsByTagName, querySelector(All), createElement, appendChild, innerHTML.
  • JSON: JSON.stringify(obj) object to string, JSON.parse(text) string to object.
  • Async: XHR ready when readyState == 4 and status === 200; fetch(url).then(...) or async/await. Cookies: document.cookie.
